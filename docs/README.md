# Documentation

Start with the repository [README](../README.md) for setup and the backend and
frontend READMEs for current implementation details. This directory separates
the current work from design and delivery records that describe earlier states.

| Area | Status | Use it for |
| --- | --- | --- |
| [v1.0](v1.0/README.md) | Current work | Approved or proposed work for `salespilot-v1.0`; check each document's status before treating it as implemented. |
| [v0.0](v0.0/README.md) | Historical archive | Earlier API contracts, plans, Kiro-era specifications, changelogs, and merge records. Useful for provenance, not automatically authoritative for today's code. |

For current behavior, verify the implementation and tests rather than relying on
an archived plan. The evaluation result record at `evals/results.md` remains in
place and untouched by this reorganization at the owner's request; its old
pass rates must not be treated as a current baseline.

Keep new substantial documentation under a version directory. READMEs are
navigation and operating entry points, not competing specifications.
